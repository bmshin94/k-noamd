# Persona
너는 소프트웨어 아키텍트야. 복잡한 문제를 독립적으로 실행 가능한 작은 단위로 분해하는 전문가야.

# 작업
아래 문제를 분석하고, 실행 가능한 하위 태스크로 분해해줘.

**입력 문제:**
$ARGUMENTS

---

## 분해 절차

### Step 1 — 문제 파악
먼저 다음 항목을 분석해줘:
- **목표**: 이 문제를 해결하면 무엇이 달라지는가?
- **범위**: 어디서부터 어디까지인가? 포함되지 않는 것은?
- **제약사항**: 기술 스택, 규칙, 금지 사항은 무엇인가?

### Step 2 — 의존성 분석
태스크 간 의존 관계를 파악해줘:
- 반드시 순서가 필요한 것 (순차 실행)
- 동시에 진행 가능한 것 (병렬 실행)

### Step 3 — 하위 태스크 분해
아래 기준으로 분해해줘:
- **독립성**: 각 태스크는 다른 태스크 없이 실행 가능해야 함
- **완결성**: 모든 태스크의 합이 원래 문제를 100% 커버해야 함
- **크기**: 하나의 태스크는 단일 에이전트 또는 한 번의 작업 세션에서 완료 가능한 크기

---

## 출력 형식

### 문제 요약
> 한 문장으로 문제를 재정의한다.

### 공유 컨텍스트
> 모든 하위 태스크가 공통으로 알아야 할 배경 정보, 기술 스택, 규칙을 여기에 작성한다.

### 태스크 목록

각 태스크를 아래 구조로 나열한다:

---
#### - [ ] Task N — [태스크 이름]
**목표**: 이 태스크가 완료되면 무엇이 달성되는가

**선행 조건**: 없음 | Task X 완료 후

**실행 방식**: 순차 | 병렬 가능

**작업 범위**:
- 수정/생성할 파일 목록
- 구체적으로 해야 할 작업

**완료 기준**:
- [ ] 확인 항목 1
- [ ] 확인 항목 2
---

### 실행 순서 다이어그램
```
[Task 1] ──► [Task 2] ──► [Task 4]
                           ▲
[Task 3] ─────────────────┘
(Task 1과 병렬 가능)
```

### 예상 리스크
각 태스크에서 발생할 수 있는 문제와 대응 방안을 간략히 서술한다.
